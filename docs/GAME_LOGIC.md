## 1. 总览与数据流 ✅

```
用户输入(键盘/鼠标/触屏)
   │
   ▼
Input controller(input.js) ──► 事件分发到 main.js 的 handler
   │
   ▼
State manager(state.js):修改棋盘/笔记/计时/错误/道具/历史
   │                    (调用 Core logic:生成/求解/校验)
   ▼
UI renderer(ui.js):重绘棋盘 + 高亮 + 弹幕吐槽(showTaunt)
   │
   ▼
Storage(storage.js):每次落子后自动存档 + 排行榜 + 关卡进度
```

核心一句话:**输入改状态 → 状态驱动渲染 → 渲染后存档**。所有逻辑在浏览器内运行,无后端、无网络请求。

## 3. 核心数据结构 ✅

棋盘统一用 **9×9 二维数组**,空格用 `0`。`createState()` 一次性创建状态对象:

| 字段 | 类型 | 说明 |
|------|------|------|
| `puzzle` | 9×9 数组 | 当前盘面(含给定值和用户填入) |
| `givens` | 9×9 布尔 | `true`=题目给定(不可改) |
| `solution` | 9×9 数组 | 生成器产出的完整解(用于校验答案、给提示) |
| `notes` | 9×9×数组 | 每格的候选数字(铅笔标记) |
| `difficulty` | `'beginner'│'easy'│'medium'│'hard'│'level'` | 难度(level=闯关) |
| `level` | 数│null | 闯关模式关卡号(1~20),null=自由模式 |
| `mistakes` | 数 | 错误次数,达 `MAX_MISTAKES`(3)判负 |
| `hintsUsed` | 数 | 已用提示数,上限 `MAX_HINTS`(3) |
| `powerupsUsed` | 数 | 已用道具总数(计入评分与排行榜) |
| `powerups` | 对象 | `{autofill:2, freeze:1, shield:1}` 剩余数量 |
| `shieldActive` | 布尔 | 护盾是否激活中 |
| `frozenUntil` | 时间戳 | 冻结截止时间,0=未冻结 |
| `elapsedMs` | 数 | 已用毫秒(计时器每秒 +1000,冻结时不加) |
| `startedAt` | 时间戳 | 本局开始时间 |
| `selected` | `{r,c}│null` | 当前选中格 |
| `noteMode` | 布尔 | 是否处于笔记模式 |
| `status` | `'playing'│'won'│'lost'` | 局面状态 |
| `history` / `future` | 数组 | 撤销/重做栈,每条 `{r,c,prev,prevNotes,next,nextNotes}` |

## 4. 核心算法 ✅

### 4.1 生成器 generator.js
1. **生成完整解 `generateFull()`**:从左上到右下逐格回溯,每格把 1-9 随机打乱后试探,合法即填;无解回退。必然产出合法完整盘面。
2. **挖空 `dig(board, givens)`**:81 格顺序打乱依次尝试挖空;每次挖空后 `countSolutions(puzzle, 2)`,**解数恰好为 1 才保留**,否则恢复。循环直到剩余给定数 ≤ 目标。
3. **难度参数**(保留给定数,挖空数 = 81 − givens):
   - `beginner` 入门:55 个给定(挖 26)— 新手友好
   - `easy` 简单:50 个给定(挖 31)— 休闲放松
   - `medium` 中等:36 个给定(挖 45)— 有点意思
   - `hard` 困难:28 个给定(挖 53)— 烧脑挑战
4. **闯关模式 `generateLevel(level)`**:共 **20 关**,难度线性渐进:
   - 给定数 = `max(30, round(60 − (level−1)×1.6))`
   - 第 1 关 60 个给定(超简单)→ 第 20 关 30 个给定(接近困难)
   - 通关第 N 关解锁第 N+1 关(存于本地进度)。
5. 入口:`generatePuzzle(difficulty)` 返回自由模式谜题;`generateLevel(level)` 返回 `{puzzle, solution, difficulty:'level', level}`。

### 4.2 求解器 solver.js
- `isLegal(board,r,c,num)`:在 `(r,c)` 放 `num` 是否违反行/列/宫。
- `countSolutions(board, limit=2)`:回溯求解,**MRV 启发式**(优先填候选最少的空格),数到 `limit` 即停。唯一性校验时 limit=2。
- `solve(board)`:返回一个完整解,无解返回 `null`。

### 4.3 校验器 validator.js
- `isValidPlacement(board,r,c,num)`:单格放入是否冲突。
- `findConflicts(board)`:返回 9×9 布尔矩阵,标记所有"行/列/宫内重复"的格。
- `isSolved(board)`:全部填满且无冲突即胜利(因谜题唯一解,合法填满 == 答案)。

## 5. 状态管理与生命周期 ✅

main.js 中的核心动作函数:

| 动作 | 逻辑 |
|------|------|
| `place(num)` | 选中格非给定:笔记模式下 `toggleNote`;否则先判**护盾**(若将填错且护盾激活 → 抵消本次错误,护盾熄灭),再 `setValue`。填入与 `solution` 不符则 `mistakes++`(满 3 判负)并弹 error 吐槽;相符则正常落子并清除同行列宫该数字的笔记。最后 `afterMove` 判胜。 |
| `erase()` | 清空选中格的值与笔记。 |
| `hint()` | 选中空格填入正解;**每局限 3 次**(`MAX_HINTS`),弹 hint 吐槽。 |
| `powerupAutofill/Freeze/Shield()` | 见[第 10 节](#10-道具系统)。 |
| `undo()/redo()` | 弹栈恢复/重做。 |
| `move(dr,dc)` | 方向键移动选中,边界钳制。 |
| `afterMove()` | 重绘 + 若 `isSolved` 则 `win()`。 |
| `win()` | 置 won → **立即 `recordIfNeeded()` 记录排行榜**(防刷新丢失)→ 关卡模式记星级并解锁下一关 → 结局面板展示用时/错误/提示/道具 + 智商评分。 |
| `lose()` | 置 lost → 不计分 → 结局面板 + 智商评分(打折)。 |
| `newGame(diff)` / `newLevel(level)` | 生成新局 → 置状态 → 启动计时 → 清存档。 |
| `resume()` | 从存档恢复(含道具/护盾/冻结/迁移旧存档 sweep→autofill)。 |

计时:每秒 setInterval,`playing` 状态下:若处于冻结期(`Date.now() < frozenUntil`)显示 `❄ 剩余秒数` 且**不加时**,否则 `elapsedMs += 1000`。

## 6. 玩法规则 ✅

- **两种模式**:
  - **闯关模式**:20 关渐进难度,通关解锁下一关,按星级记录(⭐⭐⭐)。
  - **自由模式**:入门/简单/中等/困难四档,随时开局。
- **严格错误模式**:填入与正解不符即记一次错误,**错误满 3 次判负**。
- **冲突标红**:错误填入(即使不违反数独规则)也因与 `solution` 不符而标红。
- **提示**:每局最多 3 次(H 键或按钮)。
- **道具**:每局固定配置 🎯自动填×2、⚡冻结×1、🛡️护盾×1(见第 10 节)。
- **笔记模式**:N 切换;落子自动清除同行列宫对应候选。
- **撤销/重做**:Z / Y。
- **名字门控**:首次打开必须输入玩家名(用于排行榜),存于本地。
- **自动存档**:每次落子后写浏览器存储,刷新可续玩。
- **排行榜**:按难度(含闯关)分类记录 **Top5**,综合评分制(见 9.2)。

## 7. 渲染与高亮逻辑 ✅

`ui.js`:
- `buildBoard()`:一次性生成 81 个 cell,绑定点击。宫边界 `rb`/`bb` 类加粗边线。
- `render(state, cells)`:给定值深色加粗(`given`),用户填入蓝色(`user`),笔记 3×3 小网格。
- 高亮:选中格(`selected`)、同行列宫(`peer`)、相同数字(`same`)、冲突格(`conflict` 标红)。
- `showTaunt(text, el, icon)`:棋盘上方弹幕吐槽,自动淡出。
- `showToast(msg, el)`:轻提示气泡。
- `updateNumpad()`:数字键显示剩余可填数,填满置灰。
- `updatePowerups()`:道具按钮显示剩余次数,用完置灰。
- `autofill-flash`:自动填入的格子高亮闪烁 1.5 秒。

## 9. 持久化 ✅

`storage.js`(localStorage,key 前缀 `sudoku.`):

| key | 内容 |
|-----|------|
| `sudoku.save` | 当前局存档(puzzle/givens/solution/notes/难度/关卡/错误/提示/道具/护盾/冻结/计时/状态) |
| `sudoku.scores` | 排行榜:每难度一个 Top5 数组(含旧格式自动迁移) |
| `sudoku.player` | 玩家名字 |
| `sudoku.levels` | 关卡进度 `{1:{completed,bestTime,stars},...}` |
| `sudoku.settings` | `{sound:bool, theme:'light'│'dark'│'auto'}` |

### 9.1 排行榜记录规则
- **通关即记录**(含闯关模式,记入 `'level'` 分类);失败局不记录。
- 记录内容:`{time, mistakes, hints, powerups, name, date, score}`。
- **综合评分 `score`(越低越好)** = 用时秒数 + 提示×30 + 道具×20 + 错误×60。
- 每难度保留 Top5,按 score 升序;第一名金色标记;零错误零提示零道具显示 ✨满分徽章。

### 9.2 关卡进度与星级
- **三星**:0 错误 0 提示 0 道具(完美通关)。
- **二星**:错误 ≤1 且提示 ≤1。
- **一星**:通关即可。
- 重复通关取最佳时间 + 最高星级;`getUnlockedLevel()` 返回第一个未通关的关卡号(全通关后可任意重玩)。

## 12. 智商评分系统 ✅(v2)

`iq.js` — 结局面板展示"**你的智商为 XX,<一句评语>**"。**纯属娱乐**,设计原则:**高分真诚夸,低分才损,零失误一定给好评**。

### 12.1 计算公式 `calcIQ(state)`

```
基础值:
  入门 130 / 简单 140 / 中等 155 / 困难 170(期望用时 300/420/600/900 秒)
  闯关:130 + 关卡×4(第1关134 → 第20关210;期望 200 + 关卡×15 秒)

时间调整:
  比期望快:每快 1 分钟 +2(封顶 +40)
  比期望慢:每慢 1 分钟 −1(温和)

扣分项:每个错误 −10,每个提示 −5,每个道具 −3

加分项:
  完美通关(0错误0提示0道具) +35
  零失误但用了提示/道具 +15(保证"可圈可点"不掉进嘲讽段)

失败局:总分 ×0.55
最终钳制:10 ~ 300
```

> v1 公式过于严苛(零失误通关也只拿 88 分掉进嘲讽段),v2 全面回调:基础值上调、时间/扣分减半、增加零失误保底加分。

### 12.2 段位文案 `iqLabel(iq)`
